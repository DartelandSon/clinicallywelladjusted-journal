# Clinically Well Adjusted

A custom, static journal for the life of Curtis Darlage. The website uses HTML,
CSS and a small search script. It needs no CMS, database, paid theme, publishing
plugin, or AI API key.

This is the PUBLIC website repository. It contains website code and material
cleared for publication. Private research, interview answers, correspondence,
source notes, credentials, and the full life archive belong elsewhere.

## Build

    python3 -m pip install -r requirements.txt
    python3 build.py
    python3 -m unittest discover -s tests
    python3 -m http.server 8080 --directory dist

Article source files live in content/entries. Pages live in content/pages.
Each Markdown file begins with JSON between two lines containing three hyphens.
Only documents with published set to true are included. Future entries are
excluded until their publication date. A build error leaves publication to the
last successful deployed release.

An entry requires title, path, kind ("entry"), published, date (ISO timestamp
with timezone), authorship ("ai" or "archive"), and excerpt. AI entries also
require source_note_recorded to be true after their evidence note is saved
privately. Archive entries require their original public source_url.

## Publication

Commit approved article Markdown to main using the GitHub connector. GitHub
Actions builds and tests the site, then commits the complete generated dist to
the published branch. The server reads only that branch. The editor does not
need a local shell, hosting credentials, or an AI API key. Standard GitHub-hosted
runners are free for this public repository; no paid runner or storage is used.
Do not upload private draft material to this public repository, including on
branches. Do not publish credentials or private source references in metadata.
The static deployer checks one immutable Git commit, downloads only allowlisted
public file types, checks sizes and SHA-256 hashes, then switches one symlink.
It does not execute downloaded code. The host keeps earlier releases for rollback.

The hosting deployer runs outside the public document root. It reads this public
repository without a GitHub token or hosting password. Its private configuration
specifies repository, branch, and the dedicated deployment directory. The domain's
document root points to that directory's current symlink.

The source tree is portable. The generated dist folder can be hosted by any
ordinary static web server. Hosting rules are generated by the installed deployer,
not accepted from remote article content. Preserve the Google verification file.

## Editorial contract

This is a record of a single man's life for whoever may benefit from it.
AI handles ordinary editorial work at Curtis's direction, with rare questions.
The editor's understanding of his voice is imperfect; AI entries do not imply
his personal review or authorship. Every new AI entry includes that notice.

Preserve original published dates and words in the historical archive.
First-person AI prose must be grounded in documented accounts. Never invent
events, dialogue, memories, motives, or current activity. Private research
access does not authorize publishing every private fact or another person's
personal information. Keep a private evidence note and publication ledger.
Use public or explicitly cleared material, verify broader factual claims,
and label corrections. Skip an entry when evidence is insufficient.

Each future post should reward the reader beyond a record of events: an earned
lesson, useful or surprising insight, fresh connection, deeper understanding,
or a specific unanswered question worth considering. Let that thought grow from
the documented experience and develop it in the prose. One strong thought is
enough; no generic inspirational ending, forced moral, or required lesson heading.
Privately state the reader's takeaway or question in one sentence before publishing,
and verify the draft actually delivers it. Improve the angle rather than add filler.

Preserve already-published article text and dates, including the original archive
and the accepted first new entry. New editorial preferences apply to future
writing; do not retroactively rewrite old posts without Curtis's explicit request.
Handle any necessary factual correction separately and transparently.

Curtis's length reference is "On Kicking Rocks and Bruising Butts": about 420
words. Keep entries short, direct and focused; longer or shorter is allowed
when the content warrants it. This is a guide, not a word limit.

The editor checks quietly each Sunday at 10 a.m. Indianapolis time. Aim to
publish roughly every two weeks, with additional worthwhile posts or fewer
when the material demands. There is no monthly cap. Reconcile pending entries
and avoid duplicate topics or writes; do not fill a publishing slot with filler.

Keep "On Kicking Rocks and Bruising Butts" pinned on the homepage. Its route is
configured by pinned_entry in site.json; never change it without Curtis's
instruction. Preserve the original article's text and date. New entries appear
in the ongoing record below it; the archive and RSS stay chronological.

The editor should read its durable private instructions first, check
existing entries to avoid duplicates, commit approved source to main, verify
the Actions run, then verify the live URL and deployment.json commit. Log the
confirmed public URL and commit privately. Routine success and skipped runs stay
quiet. A commit alone is not proof that the public website updated.

The Actions step "Verify live site on Stellar" waits for the hosting poll,
checks deployment.json against the immutable published commit, and compares
every public file's bytes and SHA-256 hash with the generated manifest. Its
success is required before marking an entry published. The editor can verify
this step via the GitHub connector when its web reader cannot access the site.
A failure is a pending/unverified publication, not permission to duplicate it.
